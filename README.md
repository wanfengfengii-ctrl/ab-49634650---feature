# 地震预警二进制码编配工作台

为地震预警中心的 5–8 类警报编配短二进制码表的静态前端。在受限带宽下，高频警报自动获得更短码字；码字两两前缀无关，任意连续电文都能被唯一拆分。

## 功能

- **参数录入**：警报名称、正整数预计发送频次、每类码长闭区间（1–12 位）、0–3 条保留前缀；支持 5–8 类警报的增删，本地草稿可持续修改。
- **约束求解**：每类恰分一条码字；码字两两不得互为前缀；码字既不"落入"保留前缀的子树，也不"遮蔽"保留前缀本身。
- **三级最优目标**（按优先级）：
  1. 加权码长总和 `Σ 频次 × 码长` 最小；
  2. 最大码长最小；
  3. 按警报输入顺序展开码字，逐位字典序最小（`0 < 1`，前缀短者居前）。
- **结果展示**：二叉码树（绿 = 已分配码字，红 = 保留分支，灰点 = 未使用子树）、每类码字 / 码长 / 加权贡献明细、保留分支占用、总成本与码空间占用统计。
- **同步标记隔离审计**：在已生成且仍有效的码表旁录入 3–6 位二进制同步标记，审计由 2–10 类警报（允许重复）组成的全部连续序列，确认接收设备不会在连续警报电文的码字内部误把该标记当作新帧开头。标记跨越相邻码字的出现同样纳入审计；只有标记首位恰在码字边界（含帧首）才算合法同步，码表前后端之外的截断串不作为证据。
  - **发现风险**：按"警报条数最少 → 按警报输入顺序展开的序列字典序最小 → 标记在电文中出现位置最早"稳定返回一条证据帧，展示完整比特流、每条码字边界、标记位置与涉及的警报路径，并在二叉码树与码字明细中作关联标示（琥珀色高亮）。
  - **审计通过**：明确说明 2–10 条警报的全部连续帧（给出序列总数）均未在非码字边界处出现该标记。
  - **失效规则**：同步标记不合规、码表尚未生成或输入草稿被修改时，旧审计结论立即作废且不得沿用；审计失败或结论失效后可随时回到参数区继续修订码表。
- **无解说明**：约束不可满足时明确提示"没有可用的完整分配"并给出原因；任何输入变动立即使旧结论失效。

## 算法

两阶段精确分支限界（`src/solver.js`，纯逻辑、零依赖）：

1. **阶段一**在长度元组空间搜索最优 `(总成本, 最大码长)`：以 `2^-12` 为单位的整数 Kraft 容量做可行性剪枝，用 `O(n·2^12·12)` 预计算的 **Kraft 松弛 DP** 作代价下界；叶子的可行性由带记忆化的精确分配检查判定（保留前缀的"遮蔽"约束使纯 Kraft 不等式不充分，例如保留 `00` 时码字 `0` 不可用）。
2. **阶段二**在 `成本 ≤ 最优成本、码长 ≤ 最优最大码长` 的硬约束下按字典序枚举码字，首个完整分配即字典序最小的最优解。

正确性由 `tests/` 中的手工核算用例、性质测试及与独立暴力枚举的随机对拍保证。

## 同步标记隔离审计算法（`src/audit.js`）

- **判定规则**：连续帧为若干码字的直接拼接；标记的一次出现，其首位落在码字边界（含帧首）为合法帧同步，否则为误同步风险——完全码内出现与跨相邻码字边界出现同等对待；起点在帧首之前或终点越过帧尾（即需要码表前后端之外的截断串才能形成）的出现一律不作为证据，重叠出现（如 `000` 扫过 `0000`）借助 KMP border 回退不遗漏。
- **搜索**：在"码字边界状态"上做记忆化可达性分析 `canRisk(匹配状态, 最近 m 位边界标志位掩码, 已扫描比特数, 剩余码字数)`；边界标志随每条码字逐位滚动（每条码字首位置 1，其余位置 0），匹配完成时 O(1) 查出起始位是否为边界。再按条数 `k = 2…10` 升序、警报序号升序 DFS（同深度同状态只经字典序最小前缀重建一次），按"条数 → 输入序字典序 → 最早位置"稳定取第一条风险帧。
- **代价**：状态数上界约 `m 自动机状态 × 2^m 历史掩码 × 120 比特 × 10 深度 × 8 类分支`（m ≤ 6），实测最坏毫秒级；所有标记/码表组合均有界且确定。

## 本地开发

零依赖，需 Node ≥ 20：

```bash
npm test        # 代码测试（求解器 + UI 无头冒烟）
npm run build   # 构建检查：语法校验 + 引用核对 + 产出 dist/
npm start       # 开发服务器 http://localhost:8080 （含 /healthz）
```

## Docker 部署

```bash
# 构建并启动静态服务（宿主机端口可用 PORT 配置，默认 8080）
docker compose up -d web
PORT=9000 docker compose up -d web

# 健康检查
curl http://localhost:8080/healthz   # -> ok
```

- `Dockerfile` 多阶段构建：`build` 阶段在构建期执行测试与构建检查并产出 `dist/`；`serve` 阶段用 nginx 托管静态产物，内置 `HEALTHCHECK`（`/healthz`）。
- `docker-compose.yml` 中 `web` 服务另配 Compose 健康检查；宿主机端口经 `${PORT:-8080}` 映射。

## 一次性 verify 服务

`verify` 服务依次执行 **代码测试 → 构建检查 → 健康地址冒烟**（冒烟 `http://web/healthz` 与 `http://web/`，带重试），随后以退出码结束（0 = 全部通过）：

```bash
docker compose up --build --exit-code-from verify verify
echo $?   # 0 表示测试、构建、冒烟全部通过
```

也可在无 Docker 的环境直接对任意地址执行：

```bash
HEALTH_URL=http://localhost:8080/healthz WEB_URL=http://localhost:8080/ npm run verify
```

## 输入限制与约定

| 项 | 约束 |
| --- | --- |
| 警报类别 | 5–8 类，名称非空且不重复 |
| 预计发送频次 | 1–10⁹ 正整数 |
| 码长区间 | 闭区间，1 ≤ 下限 ≤ 上限 ≤ 12 |
| 保留前缀 | 0–3 条，1–12 位 0/1 串；被更短保留串覆盖的冗余项自动忽略 |
| 同步标记 | 3–6 位 0/1 串；审计覆盖 2–10 类警报的全部连续序列（允许重复） |

字典序约定：第三级目标按警报输入顺序逐类比较码字串（`0 < 1`，一方为另一方前缀时短者居前），首个不同位决定先后。
